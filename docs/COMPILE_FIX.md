# v1.01：MQL予約語との識別子衝突修正

## 確認した原因と場所

mainの修正前コミット025d9eff99d260bb914006e311966e07431ab47dを確認しました。

- 公開中のInclude/BuySellMagicCore.mqhには、変数・引数・メンバー名としての`final`はありません。
- Experts/BuySellMagicRecorder.mq4のPendingTheory構造体には`bool final;`があり、初期化・復元・理論結果の処理で合計6か所使っていました。
- `final`はMQLのクラス修飾等に使う予約語と衝突するため、識別子として使わず、すべて`isSettled`へ統一しました。テストの参照も更新しています。

利用者のMetaEditorが示したCore側のファイル/行と、現行公開ソースの位置の違いについては、配置済みファイルとエラー一覧全文がないため原因を断定できません。mqhへEA全体を貼り付けていないか、端末/データフォルダに同名の古いファイルがないかも確認対象です。

## 後続エラー・警告について

最初の予約語エラーに続く識別子・メンバー参照の構文エラーは連鎖する可能性があります。しかし、11 errors / 3 warningsの具体的な全文・行番号はまだ提供されていません。すべてがこの衝突の派生である、または全件を解消したとは断言しません。

確認済みの衝突だけを修正し、未確認の型変換や判定式を推測で変更していません。残るメッセージがあれば、修正後のMetaEditor一覧のメッセージ・ファイル名・行番号から個別に調査します。

## 変更範囲と互換性

修正する実行コードはEA側の名前だけです。Coreの水平ドット5個以上、Digits正規化後の完全一致、陽線HIGH・陰線LOW、最初のブレイク・重複防止・結果判定を変更していません。注文機能はありません。M3-SIGNAL-AUTOは変更していません。

EAのproperty versionを1.01、起動ログを `BSM build=1.01; recorder=1.00` としました。CSVのVERSION=1.00、50列台帳と12列生値、既存ファイル名は維持します。`isSettled`はメモリの内部メンバーなのでCSVの列名には影響しません。旧台帳の復元テストも継続します。

## 見逃しと再発防止

ホストテストはC++へ最小限構文変換して実行するため、C++では文脈によって使える`final`を識別子として通していました。MQLの構文チェックを代替できていなかった点を補うため、tests/check_mql_identifiers.pyを追加しました。

EA・Coreからコメント/文字列/文字リテラルを除いて、プロジェクト内で識別子として使わないMQL予約語（final / override / abstract）を検査します。不正な宣言・引数・メンバー参照を検出する回帰例も含みます。完全なMQLパーサーではなく、これだけでネイティブのコンパイル成功とは判定しません。

EAのmq4はMQL4/Experts、CoreのmqhはMQL4/Includeへ、GitHubの各パスの内容をそれぞれ別ファイルとして配置してください。今回Coreに実行コードの変更はありませんが、配置済みの内容とGitHub版が一致することを確認します。

MetaEditorで **BuySellMagicRecorder.mq4** を開いて再コンパイルします。mqhを単独のEAとしてコンパイルしません。既存CSVは削除・修復しません。

ホストの全42ケース、CSV結合、別プロセス復元、追加の予約語検査は成功しました。MetaEditor/MT4での実コンパイルは本環境に実行環境がなく未検証です。
