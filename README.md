# BUY-SELL-MAGIC-AUTO — STEP 1

MT4用 `buy-sell-magic1.ex4` の**独立した記録専用EA**です。M1確定足の水平ドット群とブレイク候補、180秒Bid理論結果を記録します。注文・ザオプション接続・外部API・DLL・マーチンゲールは実装していません。M3-SIGNAL-AUTOのソース・設定・CSVを参照/変更する実行処理はありません。

**初期状態はバッファ調査専用**です。赤・青のmodeは未確定のため、`BuffersConfirmed=false`、両mode=-1で起動します。実測で確認するまで候補を作りません。EX4は本納品に含みません。

チャートオブジェクト（BSMObjects）と詳細iCustom/バー/DLLコンテキスト（BSMDiagnostics）を別CSVへ記録します。EA側のDLL許可がOFFと確認できた場合のみiCustomを呼び、許可設定は変更しません。価格の取得方法の切り分けとログの読み方は [docs/V103_DIAGNOSTICS.md](docs/V103_DIAGNOSTICS.md) を参照してください。

## MT4への導入

1. MT4の「ファイル → データフォルダを開く」で、その端末のフォルダを開きます。MacでもMT4内から開いてください。
2. 正規の `buy-sell-magic1.ex4` を **MQL4/Indicators/** に置きます。EX4は改変しません。
3. 本体mq4を **MQL4/Experts/**、共通mqhを **MQL4/Include/** へ置きます。MetaEditorで **BuySellMagicRecorder.mq4** を開きコンパイルします。mqh単体をコンパイルしません。実際のerrors/warningsを確認してください。本環境ではMetaEditorコンパイル未実施です。
4. **既存EAを載せていない新しいUSDJPY・M1チャートを1枚**開き、このEAを置きます。M3-SIGNAL等が稼働するチャートのEAを置き換えないでください。最初はバッファ設定を初期値のままにします。自動売買OFFでもティック/タイマーの記録を行う設計です。
5. Expertsの `BSM build=1.03; recorder=1.00; confirmed=false` と、MQL4/FilesにできるBSM専用CSVを確認します。EAを複数チャートから同じ銘柄の台帳へ同時起動しないでください。

## バッファの実測確認

`iCustom(Symbol(),PERIOD_M1,IndicatorName,SignalPeriod,ArrowPeriod,SL_pips,AlertON,Email,mode,shift)` で利用者提示の5入力を明示渡しします。3整数・2boolとして渡し、順序は提示順です。EX4の実際のextern/input宣言を読み取ったわけではないため、チャート設定を保存した.set、パラメーター画面、提供元の入力仕様と照合してください。

標準ではmode 0～7を、毎回の新しいM1確定足で読みます。MQL4で文書化されたiCustom modeは0～7です。ProbeMaxModeを8～15にした場合は、その範囲を `UNSUPPORTED_MT4_MODE` / NOT_READとして記録し、非対応のネイティブ呼出しは行いません。8以上が必要な指標なら、ソース/提供元仕様やオブジェクト描画の有無を別途確認する必要があります。

`BSMRaw_<銘柄>_M1_v1.csv` で同じ時刻の全modeを比較します。任意の過去の**確定済み**M1足は `DiagnosticBarTime` を設定すると起動時に生値のみ追加できます。例：`2026.11.09 09:43:00` と `2026.11.09 10:27:00` をそれぞれ指定して、チャートのデータウィンドウと照合します。時刻は端末のサーバー時刻です。対応する履歴がなければUNAVAILABLEログとし、近隣足で代替しません。過去の候補は生成しません。

提示された158.098、157.874等は照合対象であり、modeとの対応を確定する証拠はまだありません。Stop / Signal / Lineが同値の足もあるため、**1～2点で値が一致しただけではドットの対応を確定しません**。複数の時刻と、ドットが変化/消失する足でも確認してください。チャート表示とiCustomの計算条件・保持範囲も実機で確認が必要です。

赤ドット・青ドットを確認できたら、EAを外し、CSVをバックアップしてから、`RedDotMode` / `BlueDotMode` をそれぞれ設定し `BuffersConfirmed=true` にします。異なるmodeだけを指定できます。設定変更時には保存済み群をCONFIG行でリセットし、**これから確定する5本以上**を再び集めます。既存CSVを削除しません。

## ブレイクの判定順序

初回起動時は現在までの過去足で群を作りません。これから閉じたM1足だけを1本ずつ追跡します。

1. 前の確定足までにある同一価格の赤/青ドット群を参照します。直前まで連続し、5個以上で未使用の群だけを対象にします。
2. その後に閉じたブレイク足（shift=1）のOHLCを使用します。HIGHは `Close>Open && Open<=赤価格 && Close>赤価格`、LOWは逆の陰線/下抜けです。ヒゲだけ、同値終値、同値始終値、ラインを越えて始まった足は除外します。
3. 合格した群を使用済みにして、次のM1足の最初に受信したティックで候補を記録します。注文ではありません。ティックが秒00より遅ければ実際の検出日時もその遅れを反映します。
4. **判定後**にブレイク足自身のドットで群を更新します。したがってブレイク足のドットが消失/変化していても、直前までの水平群で判定できます。同じ価格が続けば使用済み状態を維持します。

価格が1 pointでも変われば新しい群の1個目、-1/EMPTY_VALUEや欠落なら群をリセットします。未確定足の価格・ドットは群や判定に使いません。M1のshift=0は新足の時刻確認だけです。

ゼロ・負数（-1以外）・非有限値・不自然な価格・取得エラーは価格として扱いません。v1.03ではEAのDLL許可がONまたは取得不能の場合、iCustomを呼ばずDLL_CONTEXT_BLOCKEDとして記録します。OFFへの自動変更もしません。**選択した赤/青のどちらかに異常/読取失敗があれば候補を作らず、両群をリセット**します。-1/EMPTY_VALUEは正常な「ドットなし」で、ブレイク足での消失を許容します。

サイン台帳のBAR行は候補の有無にかかわらず毎確定足を記録し、HIGH/LOWそれぞれの見送り理由を残します。OnTimerは結果処理だけを行い、新しい足の候補判定はOnTickだけです。

## 180秒Bid理論結果

予定入口はブレイク足開始+60秒、予定出口は入口+180秒です。秒の一致するBidをEAが**OnTickで受信・観測できた場合だけ**使用し、最初に観測した1秒当たり1価格を保持します。ティック時刻と観測時のTimeCurrentが一致することを確認します。OnTimerで再取得した最終気配値を新たな当時の観測とは扱いません。遅れて得た別時刻のBid、ローソク終値、過去ヒストリーで補完しません。

入口が未取得、出口の正しい秒にBidを観測できなかった、通信断/停止中だった場合はUNKNOWNです。予定出口の秒より後にTHEORY行を追記し、HIGHは上昇WIN、LOWは下降WIN、同値DRAWです。比較は保存した固定16桁のBid文字列を厳密比較し、数値再変換の丸め差による矛盾を避けます。

**MT4の観測Bidによる理論結果**であり、ザオプションの約定・判定・実損益を再現するものではありません。180秒を数本後の足で置き換えません。

## CSV・再起動・欠落・エラー

保存先はそのMT4の **MQL4/Files/**。M3の台帳とは異なる接頭辞です。

- `BSMRecorder_<銘柄>_M1_v1.csv`：50列、追記専用。BAR/RESET/CONFIG/THEORYイベント。群の全状態と候補を同じ1行へ保存してからメモリを更新します。
- `BSMRaw_<銘柄>_M1_v1.csv`：12列、全modeの生値・判定状態・エラー。原本の診断履歴です。
- `BSMDiagnostics_<銘柄>_M1_v1.csv`：41列、入力5項目、時刻/shift/エラー、EA側DLL状態。
- `BSMObjects_<銘柄>_M1_v1.csv`：30列、現在チャートのオブジェクト属性とスナップショット集計。ドットの役割は自動判定しません。

候補キーは `銘柄|M1|ブレイク足epoch`。陽線HIGHと陰線LOWは同時成立しないため方向なしでも一意です。復元では列・連番・COMMIT・キー・群の遷移・使用済み状態・結果の時刻と価格の整合性を検査します。既存の群と結果待ちを復元し、同じ足や使用済み群を再記録しません。

再起動中に閉じた未処理足があればRESETで欠落を記録し、群をクリアします。EA停止中の過去候補を取り戻したり、発注済み扱いしたりしません。通信断もログに残します。未来の結果待ちレコードは復元しますが、消えた秒単位の価格キャッシュは作り直しません。

ファイルは書込み共有を許さず、同じ銘柄へ2つの本EAを起動すると後発を停止します。既存ファイルを切り詰めません。途中行・ヘッダー違い・矛盾なら修復せず停止します。書込み/flush失敗はExpertsに出して以後の記録を停止します。成功した保存の耐久性はMT4/OS/ストレージにも依存します。必ず停止後にバックアップしてください。

2ファイル間に原子的な更新保証はありません。生値が書けても候補行が書けない場合や、flushエラー時に行が残る場合があります。既存データは消さず、再起動時に整合性を検査します。

## Mac等で候補の最新状態を抽出

Python 3のみで動作し、外部ライブラリは不要です。EA停止後の台帳コピーを使い、新しい出力先へ実行してください。

```sh
python3 analysis/export_signals.py \
  --ledger /path/to/BSMRecorder_USDJPY_M1_v1.csv \
  --out /path/to/new_signals.csv
```

元のOHLC・水平群情報を保ち、後続THEORYをキーで結合します。既存CSVや既存出力を上書きしません。生の台帳でTHEORY行だけを見ず、元のBAR行と結び付けてください。
